## 4. 代码布局与方法

| 路径 | 内容 |
|---|---|
| `jev/client.py` | HTTP 客户端、重试、密钥读取 |
| `jev/rubrics.py`、`jev/fewshot.py`、`jev/data.py` | VA 题目、Task 1 示例选择、数据读写 |
| `jev/triplets.py` | Task 2 词典方案（官方 test 结果），经 `runners/run.py --task 2` 运行 |
| `jev/extraction.py` | Task 2 BIO r3 抽取器 `BIOExtractor` |
| `jev/task2.py` | Task 2 共用：语料、AO 诊断、请求缓存、配对 VA、官方 cF1 |
| `tools/evaluate_bio_r3_dev.py`、`tools/summarize_bio_r3_dev.py` | BIO r3 完整 dev 评测与离线汇总 |
| `tools/calibrate_st1.py` 等 | Task 1 标定、泄漏审计与探针 |
| `deving/` | 开发记录；`deving/archive/` 为已放弃实验的原样代码，不可直接运行 |

**`runners/run.py --task 2` 仍运行词典方案，不是 BIO r3。** 这是有意保留的成熟默认。

BIO r3 流程：

1. 确定性切分：中日文按单字，其他语言按 Unicode 词，标点单独成 token，保留原文 offsets。这不是 Jev 内部的 subword 切分。
2. 每个 token 分别问方面 B/I/O 和观点 B/I/O 的 Choice，48 题一批；长文本按 200 token 分块，不能保证恢复跨块的跨度。state 带两条人造示例，只给 review/tokens/aspects/opinions，不给 BIO 标签和 AO 配对。
3. 代码解码：孤立 I 作为新跨度起点，相邻 B 分开；没有 CRF 或联合序列建模。
4. 方面候选加 NULL，与观点候选交叉；每对问一个 Noul（是否关联且都是完整跨度），32 题一批，阈值 **0.65**。支持 NULL aspect，不支持 NULL opinion。
5. 大小写去重后，对接受的配对问 Score V/A，16 对一批；映射到 1–9 后应用 Task 1 zero-shot shrink（`reports/calibration_20260923/parameters.json` 的 `['0'][corpus]['shrink']`），裁剪到 [1,9]，保留两位小数。

缓存标识 `EXTRACTOR_ID = 41ea479bf861` 是清理前抽取器源码的哈希。清理后的代码对缓存中全部 1,368 条记录逐请求回放一致；`tests/test_extraction.py` 固定请求摘要，改动题目或分批会让测试失败，而不会悄悄复用或丢失缓存。

## 5. 与高分方案的比较边界

来源：[官方总报告 Table 7](https://aclanthology.org/2026.semeval-1.452/)、[Takoyaki](https://aclanthology.org/2026.semeval-1.219/)。官方 test 头部队伍八语料平均约 56%–58%；Takoyaki 是**英文餐厅和英文笔电**第一（70.21% / 63.66%），不是所有语料的冠军。dev 43.51% 只能作档次参照，不能称排名或超越某队。

已借鉴并实现：BM25 三种检索分词、每路 50 示例、无纠错的两票 AO 集成（未超过 BIO r3）。尚未复现的关键点：对方用 Gemini 一次生成完整四元组；示例保留完整关联；中日文提交含错误模式纠正；投票包含类别。完整讨论见 [BM25 50-shot 记录](../deving/20260923-bio-bm25-50.md)。
