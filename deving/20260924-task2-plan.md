# Task 2 development plan, revised 2026-09-24

The ranked plan produced by the 2026-09-23 research workflow is kept in
`reports/task2_research_20260923/cache/final/plan_zh.md` (ignored; contains
diagnostic excerpts). This record tracks what was executed and how the plan
changed. All numbers are **full dev** (1,344 reviews), official scorer, macro cF1.

## Decision rules for this phase

- The user approved executing the plan and developing directly on full dev.
  The held-out-train machinery of the original plan (H1/H2 splits, test
  families, multiplicity corrections) is dropped: a full dev run costs about
  $0.5, so every arm is measured on the full split instead of simulated.
- Rules take their parameters from train or the official README. Values chosen
  by looking at dev are marked *dev-tuned*.
- The official test split is used once, when dev performance suggests the
  system is competitive with the strongest SemEval systems (their test macro is
  about 56–58%; lexicon baseline lost 3 points from dev to test).

## Revision 1: from post-processing to boundary competition

Error analysis of the stack: the dominant losses are span boundaries and
missing opinions, not links. The cached diagnostics agree: given two gold
spans, Noul at 0.65 is 97.9% precise, and when a gold pair and a boundary
variant are both candidates Noul prefers the gold one in about 90–94% of
cases. BIO r3 fails because each record offers only one boundary per span.

New arm **L1 (lattice pairing)**, replacing A2/A3 as the main line:
candidates per role = BIO argmax spans ∪ BIO-marginal lattice spans (score
≥0.2) ∪ train-affix variants ∪ train-lexicon matches; Noul on every
non-overlapping pair; accepted pairs are kept in probability order, and a pair
whose aspect and opinion both overlap a kept pair is suppressed. Oracle
candidate-pair coverage rises from 57% to about 78% macro (jpn 29% → 87%,
zho_laptop 36% → 63%). This one path covers all corpora, so jpn needs no
separate routing. Code: `jev/lattice.py`, config `lattice`.

Deferred from the original plan until L1 is measured: A7 conflict arbiter,
A4 span pre-filter, N2/N1 prompt edits, N3 cluster Choice (L1 is a cheaper
variant of the same idea), A5 VA refit.

**L1 result: 39.95 (worse).** Without suppression the lattice finds many more
gold pairs (eng_restaurant TP 335 vs 296), but independent Noul probabilities do
not rank boundary variants well enough: suppression kept the wrong variant and
FPs tripled. Multiplying Noul by the BIO span score reached only 49.9 perfect-VA
F1 (dev-tuned). An oracle that picks the gold boundary among the lattice
variants of each stack pair would give 62.4 perfect-VA F1 (stack: 53.5), so the
problem is selection, not coverage.

## Revision 2: variant choice, then a cross-validated reranker

| Arm | Full dev macro cF1 | Perfect-VA F1 |
|---|---:|---:|
| stack_v1: one Choice per stack pair and role over overlapping variants + none, 4 BM25 train examples in state | 50.49 | 54.60 |
| Reranker, lattice r1 signals, Task 1 VA shrink | 54.88 | 59.31 |
| + Task 2 VA lines fitted on 1,000 train gold pairs per corpus | 55.11 | 59.31 |
| + train edge-affix log-odds features, one model per language group | **56.46** | 60.72 |

The variant Choice changes boundaries at chance level for opinions (107 right,
101 wrong); its gain is the "none" option removing FPs. It is not used further.

Reranker (`jev/rerank.py`): logistic regression (L2 5) over each lattice pair
with lattice p >= 0.3. Signals: lattice Noul, BIO r3 Noul, lexicon-baseline
Noul, an example-conditioned span check per candidate and pair check per pair
(`jev/spancheck.py`, 4 BM25 train examples), BIO span scores, argmax/affix
membership, train counts and edge-affix log-odds, lengths, competing variants,
distance; per-corpus intercepts. Selection: score order, suppress pairs that
overlap a kept pair on both roles, threshold 0.25. Dev numbers are 5-fold
out-of-fold by record; the threshold, feature set and grouping were chosen on
dev, so they are optimistic. Single-signal AUCs on candidate pairs: pair check
0.80–0.90 (best everywhere), lattice Noul 0.75–0.86.

Tried and not adopted (perfect-VA F1 under the same CV): merged adjacent
candidates (coverage zho_laptop 63% → 75%, but 58.95 vs 59.31); BIO labels with
4 real BM25 examples instead of invented ones (span F1 unchanged; averaged
marginals +0–3 on single roles); train annotation-rate features (no change);
train-prior variant choice (worse).

Per corpus (dev cF1): eng_restaurant 76.35, eng_laptop 67.67, zho_restaurant
57.89, zho_laptop 37.84, jpn_hotel 53.58, rus 53.75, tat 51.59, ukr 53.03.

## Test decision

Official test Subtask 2 results (overview arXiv:2604.07066, Table 10): PAI
69.03 / 61.69 / 56.82 / 57.93 / 49.08 / 57.87 / 56.38 / 53.06 (eng_r, eng_l,
jpn, rus, tat, ukr, zho_r, zho_l; macro 57.73), PALI macro 57.50, AILS-NTUA
50.16, Habib University 47.15. Our dev estimate is ahead of the winner on the
English corpora, level on zho_restaurant and tat, and behind on zho_laptop,
jpn, rus and ukr. Expecting some dev→test loss, this is upper-middle and
competitive with the strongest systems on several corpora, the agreed
condition for one frozen test run.

Frozen for test (`tools/run_task2_test.py`): BIO r3 → lattice r1 with lexicon
matches → span and pair checks → per-group reranker fitted on all full-dev
candidates, threshold 0.25 → Task 2 train VA lines → official scorer.
