# 固定真实样例 BIO / 起点完整跨度 Choice 对照

> **归档说明（2026-09-23 清理）**：本实验的代码已原样移入 [`archive/`](archive/README.md)，不再维护，也不能在当前布局下直接运行。文中命令保留为当时的运行记录；结果以 `reports/` 中的汇总为准。

## 运行前冻结的协议

按 GPT Pro 建议先诊断缓存，再做一次替换性 trial 对照。不增加筛选器、修复器或 VA 调用。

- 数据、模型：项目固定数据 commit，`jev-1.13.0`；沿用四语料各 6 条的既有 trial 24。
- 两组：固定真实 train 示例 BIO；相同来源示例的逐起点完整跨度 Choice。
- 每语料固定 2 条 train 记录。排除与全部 trial/dev 规范化文本重复；目标字符串只允许唯一、精确 token 对齐；示例无重叠，两个表达形式均可示范。按 NULL、多词、多个配对及 ID 哈希确定性选取；最长 35 token。不是评测后选样。
- BIO 展示逐 token 标签；Choice 展示当前起点的完整候选和正确答案，每条示例各一个正起点、一个负起点。示例只使用原文及训练标注，不使用 VA。
- 共享标注导向规则，撤除通用“完整短语/保留所有修饰语”约束。两组使用相同 Noul 配对题及阈值 0.65；因此与旧 r3 的差异不能归因于单独的 few-shot。
- Choice 每起点长度 1–12 token，加 none；选中后从选项移除，继续询问该起点直到 none 或候选耗尽。训练中发现同起点多跨度，因此保留此能力；不移动全局 cursor，不做边界修复。
- 两组共同支持 NULL aspect 和 NULL opinion；另报去掉 NULL opinion 输出后的指标，gold 分母不变。
- 每组成功调用的输入预算 194,302 tokens，等于旧 BIO trial 97,151 的两倍。串行请求；达到预算即停止后续请求，最后一请求可能超过预算。失败请求的未知消耗另行说明。不截断候选来凑预算。
- 仅当完整 trial 的 Choice 相比本次 BIO Macro pair F1 至少 +3 个百分点，且 Micro precision 不下降超过 2 个百分点，才进入新 48 条 dev 对照。未完成的运行不报告完整 trial 分数。未通过则不扩展 dev，不自动启动替代模型。
- 报告 AO exact surface-pair Macro/Micro、TP/FP/FN、逐语料、方面/观点抽取、候选配对覆盖、NULL opinion 增量、成本。没有 VA，不是官方 cF1。

运行命令：

```bash
python3 tools/diagnose_span_choice.py
python3 -m unittest tests.test_span_choice
python3 tools/probe_span_choice.py --mode bio
python3 tools/probe_span_choice.py --mode choice
```

原始请求、示例文本和错误个案仅保存在忽略的 `reports/span_choice_20260923/cache/`；公开摘要不包含数据原文。开发实验留在 `deving/`，不写入 README 主结果表或 `logs/`。没有推送授权。

## 已完成结果

执行指纹 `b4cc21a406ed`，返回模型均为 `jev-1.13.0`。BIO 完成 24/24；Choice 完成 11/24 后达到停止线，因此**没有完整 Choice trial 分数，也未启动新 dev 48 条**。以下均为开发样本 AO exact pair F1，不是官方 cF1。

本次 BIO 的方面 F1 为 60.32%（TP19/FP19/FN6），观点 F1 为 35.90%（TP14/FP28/FN22）。历史 r3 对应 61.76%、68.42%。候选配对覆盖从历史 25/39 降至本次 14/39；后者包含 NULL opinion 候选，去掉该候选后为 13/39。

这是“真实固定示例 + 与问题匹配的示范形式 + 标注导向规则 + 共同配对措辞 + NULL opinion 支持”的整体配置结果，不能将下降单独归因于 few-shot、选样或撤除某条规则。

Choice 的 61 个配对 FP 中，31 个与某条 gold 的两侧分别相等或有子串关联，另外 30 个不满足该关系。这只是字符串结构诊断，不能把前 31 个全部判为纯边界错误。中文笔电贡献 35 个 FP。当前交集中 12 个候选已覆盖的 gold 全被配对器接受，另 5 个漏检发生于跨度候选阶段。

### 同起点继续选择与 NULL

八语料 train 中，唯一精确对齐部分的 26,789 个方面跨度出现 126 组同起点不同终点；29,930 个观点跨度出现 27 组。另有 781 个方面、340 个观点表面串重复出现或无法唯一对齐，没有强行指定位置。因此不能宣称数据不存在同起点多个答案。

Choice 完成样本共 278 道首轮抽取题，得到 88 个正选择；随后 87 道继续询问**全部回答 none**，没有增加任何 TP 或 FP。另一个正选择已耗尽该起点的候选，未发只含 none 的题。当前误报并非来自本轮“继续询问添加了边界变体”；不同起点之间仍可产生相关跨度。

NULL opinion 两组均进入同一个配对步骤，但没有任何输出达到 0.65，因此本次最终 TP/FP 没有来自 NULL opinion 的增量。gold 分母保持不变。训练示例的 NULL 元素不被伪装成显式 token 标签；配对器延续无配对 few-shot 的设置，此轮没有单独验证 NULL 教学效果。

## 旧缓存诊断

### 原 SE 的方面错误及组件价值

旧 trial SE 的 13 个方面 FP 中，4 个与 gold 子串相关、9 个无此关系；4 个 FN 全有子串相关输出。检查这 4 条 FN 的决策轨迹：1 条起点正确但终点过长，1 条起点过早，2 条起点过晚。它们不需要用“提前 none”解释；这也不是对其他数据的归因。

固定另一侧候选后，候选配对覆盖如下（保留旧 NULL aspect、不新增 NULL opinion；gold 共 39）：

| 方面 / 观点来源 | 可覆盖 gold | 候选配对数 |
|---|---:|---:|
| BIO / BIO | 25 | 111 |
| SE / BIO | 23 | 102 |
| BIO / SE | 22 | 94 |
| SE / SE | 21 | 84 |

因此旧 SE 的方面级 precision 优势，在这批数据上没有转化为比 BIO 方面更多的可恢复配对。这是离线候选统计，没有运行新的混合系统。

### 旧全文候选 dev 的分数排序

170 个已覆盖 gold 中，92 个未达到原阈值 0.8。151 个 gold 存在与其两侧有子串关系的非 gold 候选，其中：

- 90 个 gold 的分数低于该组最高分错误候选；
- 4 个并列；
- 57 个高于该组所有错误候选。

对该 dev 缓存直接扫描 0.00–1.00、步长 0.01，最优 Micro F1 仅 33.68%（阈值 0.83，TP65/FP120/FN136），历史同 dev BIO 为 46.40%。这是使用评测标签找出的乐观诊断值，**没有修改实际阈值，没有将其当作独立验证结果**。仅调整一个全局阈值，不能在此缓存上恢复至旧 BIO 水平。

## 成本、停止条件与边界

| 本轮实际运行 | 完成数 | 成功调用 / HTTP attempts | 输入 tokens | 估算费用 |
|---|---:|---:|---:|---:|
| 本次 BIO | 24 | 72 / 72 | 128,281 | $0.005388 |
| Choice | 11 | 58 / 58 | 195,527 | $0.008212 |
| 合计 | — | 130 / 130 | 323,808 | **$0.013600** |

费用按输入 $0.042 / 百万 tokens，输出免费估算；没有重试。Choice 最后一请求使 194,302 的停止线超过 1,225 tokens（0.63%），之后没有再请求。不是严格预知 token 数的硬限额。

Choice 输入分解：首轮抽取 112,530，继续询问 63,055，配对 19,942。继续询问占总输入约 32.25%，本轮没有带来新增跨度。共同 11 条上，Choice 总输入是旧 BIO 的 4.41 倍、本次 BIO 的 3.38 倍；不能拿 Choice 11 条与 BIO 24 条的总价比较效率。完整短语选项和当前示例形式均增加了输入，本轮未拆开测量各自影响。

按冻结协议，本轮在 trial 停止：Choice 未满足预算内完成的条件；固定样例 BIO 完整 trial 未改善历史结果。没有扩展 dev，没有新增修复层，没有启动 Qwen / GLiNER，也没有更换生产基线。**结果约束的是这次具体配置，不能据此证明所有 few-shot、所有完整跨度 Choice 或 Jev 本身都无效。**

两个针对性单测通过：起点继续选择/不同起点重叠/NULL 配对/不传入 query gold；原文 offsets 与训练示范答案对齐。旧 extractor 未修改。开发结果未进入 README 主表或 `logs/`，未 commit 或 push。
